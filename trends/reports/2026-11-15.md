## 1. Code Mode (v2.1.323, 12/11): đơn vị hành động của agent chuyển từ **một tool call** thành **một chương trình** — và lưới kiểm duyệt chuyển theo nó, mất đi phần giá trị tính lúc chạy

**What:** Claude Code `2.1.323` thêm **Code Mode**, một tính năng **thực nghiệm, tắt mặc định**: thay vì xin từng tool call rồi đọc kết quả rồi quyết định bước sau, Claude **viết một đoạn JavaScript** gọi các tool, và Claude Code chạy đoạn đó trong session. Bật bằng biến môi trường `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`.

Ví dụ ngay trong tài liệu — nâng một retry limit, gồm tìm file, sửa file, chạy test, trong **một** đoạn:

```javascript
const files = await $`rg -l "function retryPolicy" src`.text();
const target = files.trim().split("\n")[0];
await edit(target, "maxAttempts: 3", "maxAttempts: 5");
({ edited: target, tests: $`npm test -- retryPolicy`.nothrow() });
```

Dòng cuối là phần **được trả về cho Claude đọc** — tức đoạn code tự chọn lọc cái gì vào context. Đó là toàn bộ lý do tính năng này tồn tại.

Các chi tiết vận hành đáng ghi:

- **Trong hội thoại bạn thấy *tool call*, không thấy code** (ví dụ thấy diff của `edit`). Muốn xem code: `Ctrl+O` mở transcript viewer, mỗi đoạn là một hàng **Code** gập lại.
- **Tool chạy code tên là `REPL`.** Muốn tự kiểm code: viết `PreToolUse` hook match `REPL`, đọc JavaScript từ `tool_input.code`.
- **Session bị "nhuộm màu".** Banner đầu session: `Code Mode (experimental) is on · this session can be resumed only with Code Mode on`. Resume mà không bật lại biến môi trường thì Claude Code **từ chối resume**. Chiều ngược lại cũng đúng: session mở khi chưa bật thì resume vẫn không có Code Mode, dù biến đã bật.
- **Trần thời gian:** chạy chờ (foreground) **tối đa 10 phút**, *tính cả thời gian bạn đứng ở permission prompt*; chạy nền **tối đa 2 giờ**, nhưng chạy nền chỉ có nếu session **bắt đầu** ở auto hoặc `bypassPermissions` mode.
- **Công tắc tổ chức một chiều:** đặt `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=0` trong managed settings là **chặn được cả tổ chức**; nhưng managed settings **không bật được** Code Mode cho người dùng. Và `0` ở một chỗ thắng `1` ở chỗ khác.
- **Repo bạn clone về không bật được Code Mode cho bạn:** Claude Code **bỏ qua biến này trong settings file của project**. Đây là một quyết định thiết kế đúng, và đáng ghi vào decision-library như một mẫu: *biến môi trường nào thay đổi biên giới tin cậy thì không đọc từ project settings*.

**Và đây là phần quan trọng nhất, phần đánh đổi.** Tài liệu liệt kê thẳng, không che:

- **`deny` / `ask` rule và `PreToolUse` hook vẫn chạy cho từng tool call** mà code gọi. Bạn **không** phải sửa rule hay matcher. Tốt.
- **Nhưng ở auto mode, classifier duyệt *đoạn code*, không duyệt từng tool call** — và tài liệu nói rõ: **nó không thấy các giá trị tính lúc chạy**, ví dụ một đường dẫn lấy ra từ output của `rg`. Trong đoạn ví dụ trên, `target` là đúng loại giá trị đó. Lời khuyên của chính tài liệu: *giữ rule hoặc hook cho những call bạn buộc phải kiểm soát*.
- **Ở các permission mode khác, code chạy *không có* review nào**, và bạn bị hỏi từng call như bình thường.

Thêm hai chế độ lỗi mà tôi cho là đáng chú ý hơn cả bản thân tính năng:

**(a) Một đoạn code mới chạy khi đoạn cũ còn đang chạy ⇒ đoạn cũ *mất* review của classifier.** Claude Code khi đó hỏi bạn về những call còn lại của đoạn cũ, kèm **đồng hồ đếm ngược**:

```
Claude Code will automatically block this request in 1:59, to avoid holding up an unattended session
```

Hết đồng hồ: call đó **bị từ chối**, và những call sau lẽ ra cũng hiện đếm ngược thì **bị từ chối luôn, không hỏi nữa**. Muốn hỏi lại thì phải gửi Claude một tin nhắn. Với phiên không người trực, đây là một đường thất bại im lặng — và nó nằm **bên trong** auto mode, chứ không phải khi auto mode tắt.

**(b) Hook timeout trở thành trạng thái *dính* của cả session.** Tài liệu viết: lỗi `the hook did not finish` xảy ra khi hook của bạn timeout *"on a call from Claude's code, **or on any other tool call once Claude has run code in the session**"*. Tức là: Claude chạy **một** đoạn code, và từ đó trở đi, **mọi** tool call trong session chịu ngữ nghĩa fail-closed của hook timeout — kể cả các call thường, kể cả khi `onFailure` **không** được đặt. Cùng loại: `the hook failed` (hook không start được, bị kill, exit 126/127/>128, HTTP error, output không hợp lệ) **từ chối call ngay cả khi `onFailure` không đặt**. Muốn cho qua thì phải đặt `"onFailure": "continue"` trên hook đó.

Đối chiếu báo cáo 11/10 (mục 1: tầng hook vốn **fail-open**, `onFailure: "block"` vá được phần lớn): tuần này Code Mode **đảo mặc định đó cho cả session** sau đoạn code đầu tiên. Không có dòng release note nào nói điều này; nó nằm trong bảng troubleshooting của trang tài liệu.

**(c) `UserPromptSubmit` hook chạy trên *output của code*.** Khi code chạy nền được, hook `command`/`http`/`mcp_tool` trên event `UserPromptSubmit` cũng chạy trên output của code — nên một hook chặn vô tình sẽ giấu kết quả của Claude. Phân biệt bằng `source == "poll_event"` trong input của hook.

**Bức tường điều kiện — đọc kỹ phần này trước khi định dùng.** Code Mode **chỉ** chạy khi: `claude` tương tác trong terminal (**không** `-p`, **không** Agent SDK, **không** VS Code panel, **không** desktop app, **không** cloud session); **native build**; model Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.2; tài khoản Claude subscription hoặc Console **trực tiếp với Anthropic API** (không gateway, không Bedrock, không Claude Platform on AWS, không Google Cloud Agent Platform, không Microsoft Foundry); tổ chức **không** dùng HIPAA config hay zero data retention; Windows thì phải có Git for Windows. Và **không** chạy được khi có: `apiKeyHelper`, agent teams (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`), OpenTelemetry export, `DISABLE_TELEMETRY` (vì nó cần feature flag tải từ Anthropic), `--restricted`, `REPL` nằm trong `--disallowedTools` hoặc `deny` rule, **hoặc một mod đang kiểm tra tool call**.

**Fit:** **Khớp định hướng cao nhất trong 17 tuần của routine này — nhưng áp dụng được *bằng không* cho chính routine này.** Nói rõ hai chiều:

*Khớp định hướng:* Dự án này tồn tại để **tốn ít công sức nhất**. Chi phí và độ chậm của một agent run gần như tỉ lệ với **số lượt đi về với model**, không với số tool call. Code Mode tấn công đúng biến đó: nhiều call thành một lượt, và đoạn code **tự lọc** cái gì vào context thay vì nhồi mọi output vào. Trong 17 tuần, mọi mục báo cáo trước đều là *một cái núm trên cùng một vòng lặp* — đây là lần đầu **vòng lặp đổi hình**.

*Áp dụng vào quy trình hiện tại:*
- **Routine này (cloud session, chạy không người trực): không dùng được, dứt khoát.** Cloud session bị loại tường minh; `-p` và Agent SDK bị loại; OTel bị loại. Ba lý do độc lập.
- **Project1 qua Agent SDK hoặc `-p`: không dùng được.** Đây là giới hạn đáng chú ý nhất về mặt chiến lược: Code Mode là tính năng **chỉ dành cho người ngồi trước terminal**, không phải tính năng để tự động hoá.
- **Terminal local của bạn: dùng được**, nếu đổi sang kênh `latest` (vì `stable = 2.1.311` < `2.1.323`), dùng native build, và tài khoản nối trực tiếp Anthropic API.
- **Xung đột đáng ghi vào kế hoạch:** Code Mode **không khởi động được nếu có một mod đang kiểm tra tool call**. Mods là mục 1 của báo cáo 20/09 và là chủ đề mục 3 của báo cáo này. Tức mục 1 và mục 3 tuần này là **một ngã ba, không phải một chồng**.

*Mục nên vào decision-library — và nó không phải "bật Code Mode":*
> **"Code-as-action đổi reviewability lấy số lượt đi về."** Khi agent hành động bằng cách viết chương trình, lớp duyệt dịch chuyển từ *từng hành động* sang *ý định được viết ra*, và **mất phần giá trị chỉ biết lúc chạy**. Hệ quả vận hành: những call bạn buộc phải kiểm soát thì đặt ở `deny` rule hoặc `PreToolUse` hook (hai thứ này vẫn chạy per-call), **đừng** dựa vào classifier. Và mọi lợi ích phải tự đo, vì nhà cung cấp không công bố số.

**Why selected:** Ba lý do, theo thứ tự quan trọng. **(1)** Đây là thay đổi duy nhất trong tuần — và theo tôi là trong 17 tuần — làm đổi **đơn vị hành động** của agent chứ không phải đổi một tham số; và nó có hậu thuẫn độc lập trong literature (Cloudflare 2025, Anthropic 11/2025, NVIDIA 2026), nên không phải tin nhất thời. **(2)** Cái giá nó trả rơi **chính xác** vào chỗ báo cáo 08/11 mục 3 vừa nói tới: lưới đỡ của phiên không người trực. Classifier chuyển từ call sang code và mất giá trị runtime; đoạn code mới làm đoạn cũ mất review; hook timeout thành trạng thái dính cả session. **(3)** Đây là ca mẫu đẹp cho việc **phản biện con số**: một cơ chế thật, không có số đo nào từ nhà cung cấp, và bốn con số lưu hành trên mạng đều thuộc về thứ khác. Nếu chỉ lấy một thứ từ mục này: lấy cái bảng bốn con số đó.

## 2. Fable 5.2 thành model Fable mặc định (09/11) — giá giảm 20% ở mọi dòng, nhưng **thinking block nay bị khoá vào *tài khoản* và vào *họ model***, và lựa chọn model cũ của bạn **tự chuyển** sang bản mới

## 3. Trong khi `2.1.321`–`2.1.325` bịt khoảng mười lăm lỗ sandbox, **mods được cấp một đường vòng qua `ask` rule và qua cả `dontAsk`** — hệ phân quyền tách thành hai tầng, và `deny` là thứ duy nhất với tới tầng hai

**What:** Hai dòng trong CHANGELOG `2.1.321` (09/11), đọc rời thì nhỏ, đọc cùng nhau thì đổi biên giới tin cậy:

> *"Changed mods' own tool calls (`$.tool.call`, `$.mcp.call`) to raise no permission prompt, **even under your own ask rules or in `dontAsk` and `-p` runs**; deny rules and organization policy still apply"*
>
> *"Changed mods Claude writes to turn on **without asking** in auto and bypass modes, **even with managed `allowUnsandboxedCommands: false` or `allowManagedDomainsOnly`**, and not to load in `dontAsk` mode"*

Tức: **tool call do một mod tự phát ra không đi qua `ask` rule của bạn, và không bị `dontAsk` chặn.** `deny` rule và policy của tổ chức vẫn áp. Và mod do chính Claude viết trong session thì ở auto/bypass mode **tự bật không hỏi**, kể cả khi managed settings đã tắt unsandboxed command.

**Nền của hai dòng đó mới là chỗ đáng chú ý: cùng hai bản release, Anthropic bịt khoảng mười lăm lỗ theo chiều *ngược lại*.** Danh sách (đều từ CHANGELOG `2.1.321`/`2.1.323`):

- Sandbox macOS/Linux/WSL **bỏ qua quyền ghi cấp qua symlink** trong thư mục ghi được mà trỏ ra ngoài hoặc trỏ vào đường dẫn không tồn tại — phải cấp đường dẫn thật.
- `git worktree add` / `move` / `remove` **fail read-only** trong sandbox; commit trong một worktree mà session không được mở ở đó hoặc không được cấp **cũng fail**, kể cả worktree nằm trong project.
- Tạo worktree **từ chối** checkout có `.git` là link hoặc chứa hard link (layout kiểu `git-new-workdir`, bản copy `cp -al`) — phải clone thường.
- `/security-review` **hỏi trước khi chạy**; lệnh git inline trong skill **dừng lại** ở bare repository worktree và thư mục tương tự cho tới khi bạn cho phép (ngoài auto và bypass).
- "Don't ask again" mà sinh ra một allow rule **trông như chứa secret**, hoặc sẽ ghi vào một `settings.local.json` mà git đang track, nay **chỉ sống trong session** và **không được lưu**.
- `PreToolUse` hook trả "allow" **nhưng permission check sau đó lỗi** ⇒ Claude Code nay quyết định như thể **không có hook nào trả lời** (trước đây "allow" thắng).
- Permission check lỗi trên input mà một `PermissionRequest` hook đã viết lại ⇒ **hỏi lại**, hoặc **từ chối** ở nơi không ai trả lời được.
- Start-up **dừng** khi file `--settings` không phải JSON hợp lệ **và có key `sandbox`** — kể cả khi key đó tắt sandbox.
- Approval cho MCP server trong project (`.mcp.json`) nay **khớp đúng tên server**; entry viết theo cách khác **hỏi lại**.
- Self-hosted runner dưới `--trust-workspace false` và session VS Code trong thư mục chưa tin: settings của repo **không còn tắt được hook của bạn** hay bật/tắt plugin.
- `glab config set` không `--global`/`--host`, và `glab config edit --local`, **fail read-only** trong sandbox.
- `cp`/`mv` gọi bằng đường dẫn (`/bin/cp`) nay chịu **cùng** kiểm tra đường dẫn như `cp`/`mv`.
- Bash permission check: "một số lệnh có thể chạy khác với cách đã được kiểm nay **phải xin phép**", và cùng một lệnh nay **cho cùng một câu trả lời** đáng tin cậy hơn trên máy chậm/tải cao.
- macOS: sandbox làm `lsof` và tool tương tự **thấy ít hơn** về process mà lệnh không tự khởi tạo.
- Và một thay đổi về **phạm vi credential**: ripgrep và phần lớn lệnh git nội bộ của Claude Code nay chạy **không có phần lớn token đăng nhập và API key** — nên một credential helper hoặc hook nằm dưới một lệnh git như vậy **không còn tìm thấy chúng**.

Thêm hai điểm làm rõ hướng đi: `2.1.323` **giảm** quyền của *hook* trong mod (hook `*`, theo namespace, hoặc negated trên `engine.create` nay **chỉ quan sát**; muốn thêm/giữ lại một `$` noun thì phải hook `engine.create` **đúng tên**; `claude plugin validate` **fail** mod có `engine.create` hook không viết theo đúng một dạng được chấp nhận), trong khi `tool.list` plugin hook nay áp cho **model và mọi agent**.

**Đọc cấu trúc — đây là phần tôi cho là đáng vào decision-library.** Hệ phân quyền của Claude Code nay có **hai tầng**:

| | Tầng 1 — *thứ Claude xin* | Tầng 2 — *thứ harness và phần mở rộng của nó làm thay bạn* |
| --- | --- | --- |
| Gồm | tool call của model và của subagent | `$.tool.call` / `$.mcp.call` của mod; mod do Claude viết tự bật; lệnh git/ripgrep nội bộ |
| `allow` / `ask` | ✅ áp | ❌ **không áp** |
| `deny` | ✅ áp | ✅ **áp** |
| `dontAsk` | ✅ auto-deny | ❌ **không chặn mod** |
| classifier (auto mode) | ✅ | không nêu |
| org policy | ✅ | ✅ |

**`deny` là thứ duy nhất với tới cả hai tầng.**

**Credibility:** **Cao, và quan trọng là có *hai* trang Anthropic xác nhận độc lập.** Chi tiết:

*Nguồn chính:* CHANGELOG chính thức trên `code.claude.com` — hạng nhất.

*Xác nhận độc lập, và nó đáng kể:* khi tìm nguồn đối chiếu, tôi gặp một thứ **thoạt trông như mâu thuẫn**: trang tài liệu `permission-modes` nói `dontAsk` **tự động từ chối** mọi call lẽ ra sẽ hỏi — nghe trái ngược với "mod không bị hỏi". Nhưng đọc tiếp thì chính trang đó có câu cảnh báo riêng: **"a mod you installed can still approve some of those calls."** Tức trang tài liệu `dontAsk` **khẳng định lại** điều CHANGELOG nói, bằng câu chữ khác, ở một trang viết cho mục đích khác. Hai trang Anthropic sở hữu, viết độc lập, khớp nhau ⇒ đây **không** phải tôi đọc sai một dòng release note.

*Nguồn thứ cấp:* một bài DEV Community ngày 09/11 đọc hai dòng đó đúng như tôi đọc. Chỉ một nguồn thứ cấp — nhưng vì nguồn chính là tài liệu chính thức kép, điều đó không làm giảm độ tin.

*Những gì tôi **không** xác minh được, nói rõ:*
1. **Tôi không chạy thử được.** Session này là cloud session, không có mod nào cài, và mods chỉ chạy ở terminal. Nên câu *"deny rules and organization policy still apply"* là **lời khẳng định của Anthropic, tôi chưa kiểm chứng bằng thực nghiệm**. Đây đúng là câu quan trọng nhất của cả mục, và nó là câu duy nhất tôi phải tin không có đối chứng.
2. **Tài liệu không nói *những call nào*** trong `dontAsk` mà một mod "vẫn approve được". "Some of those calls" là nguyên văn. Phạm vi thật của tầng 2 là chưa xác định.
3. Không có nhân viên Anthropic nào bình luận về thay đổi này; không có công bố kiểu CVE. **Đây là một quyết định sản phẩm, không phải một lỗ hổng** — tôi không trình bày nó như lỗ hổng.

**Fit:** **Khớp định hướng trực tiếp, và nó *đính chính khuyến nghị số một của báo cáo tuần trước*.**

Báo cáo 08/11 mục 3 kết luận: chạy không người trực thì đặt `permissions.denyInsteadOfPrompting`. **Khuyến nghị đó vẫn đúng, nhưng tuần này nó thành thiếu.** Lý do: `denyInsteadOfPrompting` và `dontAsk` quản **tầng 1**. Nếu có mod được cài, các `$.tool.call` / `$.mcp.call` của nó **không đi qua đó**. Khuyến nghị đầy đủ nay là **hai dòng, không phải một**:

> Chạy không người trực ⇒ `permissions.denyInsteadOfPrompting` **cộng với một danh sách `deny` tường minh** cho những thứ bạn thật sự không muốn xảy ra. Vì `deny` là tầng duy nhất với tới cả mod.

*Phép kiểm một phút cho Project1 và cho routine này:* liệt kê mod/plugin đang bật (`/plugin`, `claude plugin list`). Với **mỗi** mod, hiểu rằng tool call tự phát của nó chạy **không hỏi**, bất kể `ask` rule của bạn. **Nếu bạn không kể tên được từng mod đang bật, thì `denyInsteadOfPrompting` không phải cái hàng rào bạn tưởng.** Riêng với dự án này, câu hỏi cụ thể là: có mod nào do Claude tự viết trong một session auto mode trước đây còn sót lại không — vì loại đó **tự bật, không hỏi**.

*Mục vào decision-library:* báo cáo 06/09 mục 2 đã mở một danh sách đang chạy — "bốn cách một permission rule âm thầm không có hiệu lực". **Tuần này thêm cách thứ năm: rule thuộc loại `ask`, và hành động đến từ tầng 2.** Nguyên tắc nén lại: **"một permission rule chỉ rộng bằng cái tầng nó với tới."**

*Và một lưu ý về lập kế hoạch:* mục 1 và mục 3 **loại nhau**. Code Mode từ chối khởi động khi có một mod kiểm tra tool call. Nên nếu Project1 đi theo mods (20/09), nó **không** đi được theo Code Mode, và ngược lại. Chọn một.

**Why selected:** Vì trong cả tuần, đây là thay đổi duy nhất **làm một khuyến nghị mà routine này vừa đưa ra tuần trước trở thành thiếu sót** — và với một dự án mà toàn bộ giá trị nằm ở thư viện quyết định, một mục sửa thư viện quan trọng hơn một mục thêm vào nó. Lý do thứ hai: nó là **mục thứ năm trong một danh sách dự án này giữ từ 06/09**, nên nó có giá trị tích luỹ, không chỉ giá trị tin tức. Lý do thứ ba, và là lý do nó thắng các ứng viên khác: mọi thứ còn lại tuần này **thêm năng lực**; riêng mục này **đổi ai là người quyết định** — và tương phản với mười lăm lỗ được bịt cùng hai bản release làm nó khó đọc sai thành "Anthropic đang nới lỏng bảo mật". Họ đang **thắt** gần như mọi chỗ, và **nới đúng một chỗ mới**: chính cái lớp mở rộng mà họ vừa mời mọi người dùng hai tháng trước.

## Đính chính và bổ sung cho báo cáo tuần trước (08/11)

**(1) Mục "chưa có eval" của tuần trước nay có tài liệu phương pháp chính thức — nhưng là eval *an toàn*, không phải eval năng lực.** Tuần trước tôi xếp `/claude-api latency-optimize` vào danh sách không chọn với lý do "cần có eval sẵn mới dùng được, mà Project1 chưa có". Ngày **13/11**, Anthropic Engineering đăng **`Building strong safety evaluations`** (https://www.anthropic.com/research/building-strong-safety-evaluations), **tám tác giả có tên** (Ruth Appel, Evan Frondorf, Jeremy Hadfield, Rebecca Hiscott, Kamya Jagadish, Shayne Longpre, Madeleine Tucker, Brett Wittmershaus). Bài nói về eval **an toàn** (có footnote trỏ sang bài khác cho eval năng lực), nhưng phần thống kê và kỷ luật báo cáo thì chuyển sang được nguyên vẹn:

- **Cỡ mẫu tối thiểu:** ít nhất **100 item** cho eval multi-turn phức tạp, **1.000 item** cho eval single-turn đơn giản. Dưới ngưỡng đó là đang đo nhiễu.
- **Preregister** metric và ngưỡng *trước khi* chạy; báo cáo **khoảng tin cậy**; dùng **so sánh theo cặp** (paired comparison).
- **Calibrate grader với nhãn người**; tiêu chí phải **nguyên tử và nhị phân**.
- **Đừng so điểm khi cấu hình khác nhau** — và đây là con số đáng nhớ nhất cho dự án này: cùng một model, cấu hình **API so với claude.ai lệch tới 34 điểm phần trăm** trên eval multi-turn. Một chênh lệch **98% so với 94%** trong bài **không đạt ý nghĩa thống kê**.
- Chạy eval trong **sandbox không có internet**, có **monitoring thời gian thực** để dừng được giữa run.
- Công cụ được nêu: Inspect (UK AISI) và Petri (Anthropic).

**Vì sao đây là đính chính, không phải mục số 4:** nó là phương pháp, không phải thay đổi hệ thống, và Project1 phải **dựng** hạ tầng eval trước đã — tức nó *thêm* công sức trước khi giảm. Nhưng nếu có ngày dựng eval, bốn con số trên là sàn, và `/claude-api latency-optimize` mới dùng được.

**(2) Tôi bỏ sót một setting có thật, và nó không thuộc tuần này: `permissions.blockWritesOutsideWorkingDirectories` có từ `2.1.314` (30/10).** Tuần trước tôi báo cáo `denyInsteadOfPrompting` mà không nêu setting này; nó lẽ ra thuộc báo cáo 01/11. Nội dung: `Write`, `Edit`, `NotebookEdit` **từ chối đường dẫn ngoài working directory, ở mọi permission mode — kể cả `bypassPermissions`**. Hai cảnh báo (nguồn thứ ba, tôi chưa đọc settings reference chính thức): nó **không** che lệnh ghi qua shell, nên phải đi cùng sandbox; và khi bật, Claude **không sửa được** chính file settings của Claude Code. Bản đối ứng chiều đọc, `blockReadsOutsideWorkingDirectories`, cũ hơn (`2.1.257`). **Kèm một đính chính nhỏ về nguồn:** một kết quả tìm kiếm tuần này gán setting này cho `2.1.321` — **sai**; CHANGELOG ghi `2.1.314`, ngày 30/10.

**(3) Nối tiếp báo cáo 04/10 mục 2 (cửa sổ 1M và "autocompact thrashing"): `2.1.323` thêm một chế độ lỗi *cứng* bên cạnh chế độ lỗi *trôi*.** Context window giả định cho một **model ID mà Claude Code không nhận ra** đổi từ 200K sang **1M**. Và có cảnh báo mới: session chạy trên model của nhà cung cấp khác có cửa sổ nhỏ hơn, **một khi đầy, có thể lỗi *mọi* lượt cho tới khi `/clear`** — đặt `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` **trước khi** nó đầy. Tức "thrashing" của 04/10 nay có em sinh đôi: **thất bại cứng, không phải thất bại trôi**.

**(4) Khoảng cách `stable` ↔ `latest` giãn từ 8 lên 14 bản, và `stable` đứng im cả tuần.** Xem bảng ở đầu báo cáo. Hệ quả cụ thể tuần này: ai ghim `stable` thì **không thể** có Code Mode (cần ≥ `2.1.323`) — tài liệu nói thẳng điều đó.

## Ứng viên đã cân nhắc nhưng không chọn

- **`Building strong safety evaluations` (13/11)** — ứng viên sát nhất với một vị trí trong ba. Chuyển xuống mục đính chính vì nó là phương pháp eval **an toàn** (không phải năng lực), và vì áp dụng nó đòi hỏi **dựng thêm hạ tầng** trước khi tiết kiệm được công sức — ngược trục "ít công sức" ở bước đầu. **Nếu Project1 quyết định dựng eval, đây là bài đọc đầu tiên.**
- **Self-hosted Claude Managed Agents (release note 12/11)** — chạy **toàn bộ** service Managed Agents trên hạ tầng của bạn, không chỉ self-hosted sandbox; agent, session và session history lưu ở đó; request model gửi tới provider bạn chọn (mặc định Anthropic); phải liên hệ account team để xin truy cập. Không chọn: dự án một người, không có hạ tầng và không có lý do pháp lý để tự host.
- **Trần tin nhắn giữa các session đi 10 → 20 (`2.1.321`) rồi 20 → 100.000 (`2.1.323`) trong ba ngày**, kèm **xác thực team lead** cho split-pane teammate (teammate sống lâu hơn lead thì yêu cầu của nó **bị từ chối**; plan approval phải **gửi lại** sau `/clear` hoặc `/resume`). Nối tiếp báo cáo 09/08 mục 1. Một mức trần tăng **5.000 lần** trong ba ngày là tín hiệu rằng Anthropic vừa đổi ý về việc agent nhắn cho agent ở quy mô nào. Không chọn làm mục riêng vì dự án một người chưa chạy nhiều session song song — nhưng đã dùng làm chứng cứ cho mục 3 (cùng mạch "harness làm thay bạn").
- **Plugin version gating `engines["claude-code"]` trong `plugin.json` (`2.1.323`)** — plugin ngoài khoảng version đã khai báo thì **không được cài, cập nhật hay nạp**, và install/update **chọn bản mới nhất vừa khoảng**. Kèm: `claude plugin validate` nay **type-check module hook TypeScript** của plugin (mỗi phát hiện là warning; `--strict` thì fail). Nối tiếp `claude-lock.json` ở báo cáo 13/09 — chuỗi cung ứng plugin có thêm khoảng version. Không chọn: Project1 không publish plugin. Đáng đọc lại nếu có ngày publish.
- **`CLAUDE_CODE_DISABLE_AGENT_PROGRESS_SUMMARIES=1`** (có từ `2.1.318`, được ghi vào CHANGELOG ở `2.1.323`, kèm issue `anthropics/claude-code#86879`) — tắt progress summary của subagent **và tắt luôn các request model sinh ra chúng**. Đây là **dòng áp dụng được ngay nhất trong cả CHANGELOG tuần này**: một biến môi trường, cắt một khoản chi phí mà không ai nhìn. Không chọn làm mục vì nó là một cái núm, không phải một xu hướng — nhưng nếu Project1 có chạy nhiều subagent thì đặt nó.
- **`CLAUDE_CODE_OVERLOADED_RETRY_MAX_DELAY_MS` nâng trần 64s → 300s (`2.1.323`)** — liên quan trực tiếp tới routine không người trực: chịu được đợt overload dài hơn thay vì chết giữa run.

- **Lệnh git/ripgrep nội bộ của Claude Code nay chạy không có phần lớn token đăng nhập (`2.1.323`)** — thu hẹp phạm vi credential, đi cùng mạch báo cáo 09/08 mục 2 (credential masking). Đã gộp vào chứng cứ của mục 3.
- **Khoảng mười lăm thay đổi sandbox/permission khác trong `2.1.321`–`2.1.325`** (symlink, worktree, `glab`, `/security-review`, `cp`/`mv` theo đường dẫn, `.claude` được bảo vệ, fix bảo mật giải mã zstd ở `2.1.325`…) — đã gộp vào mục 3, vì giá trị của chúng nằm ở **tương phản** với đường vòng của mods, không ở từng cái riêng lẻ.

## Tổng kết ngắn

Ba mục tuần này không phải ba tin rời; chúng là **ba lớp của cùng một câu hỏi: ai quyết định, và quyết định trên cái gì.**

**Mục 1** đổi *vật thể được duyệt*: từ một tool call sang một chương trình. Lợi ích là số lượt đi về — biến chi phí thật của một agent run. Giá phải trả là lớp duyệt **mất phần giá trị chỉ biết lúc chạy**, cộng ba chế độ lỗi mới mà không dòng release note nào nói. **Mục 2** đổi *đường biên của trạng thái*: thinking block nay không vượt được tài khoản, không vượt được họ model, và advisor phải cùng họ — tuần thứ ba liên tiếp một cơ chế mới **cấm trộn model trong một luồng**, đúng cái mà báo cáo 02/08 của chính dự án này từng khuyên. **Mục 3** đổi *ai là chủ thể hành động*: tool call của mod không đi qua `ask` rule, trong khi mười lăm lỗ khác bị bịt — hệ phân quyền tách thành hai tầng và `deny` là thứ duy nhất với tới cả hai.

Mạch chung của mười bảy tuần, đọc lại: tuần 08/11 tôi viết rằng "các nút bắt đầu khoá nhau". Tuần này đi thêm một bước, và nó không dễ chịu: **các nút bắt đầu khoá *nhau theo cặp loại trừ*.** Mods **hoặc** Code Mode, không cả hai. Thread nhanh **hoặc** đổi model, không cả hai. Thinking block dùng lại **hoặc** đổi tài khoản/model, không cả hai. Đây không còn là bảng đánh đổi có trọng số — đây là **ngã ba**. Thứ đáng đưa vào `decision-library` tuần này vì vậy không phải một bảng, mà là **một danh sách các lựa chọn loại trừ, kèm điều kiện để biết mình đang ở nhánh nào.**

Và một quan sát về phương pháp, vì nó sẽ còn lặp lại: **mục 1 là một tính năng có thật, hậu thuẫn lý thuyết vững, và không một con số hiệu quả nào do nhà cung cấp công bố** — trong khi bốn con số đang lưu hành trên mạng đều thuộc về thứ khác. Nếu dự án này giữ lại đúng một thói quen từ báo cáo tuần này, hãy giữ thói quen tra xem **con số đang nói về cái gì** trước khi tra xem nó to bao nhiêu.

**Nếu chỉ làm một việc tuần này:** chạy `/model` và `/status`, xem routine này và Project1 **thật ra đang chạy model nào** (mục 2). Lý do nó đứng trước mọi việc khác: đây là thay đổi duy nhất trong tuần **đã xảy ra với bạn mà không hỏi** — lựa chọn Fable 5.1 đã lưu tự chuyển sang `fable` trên Pro/Max. Mất một phút, và nếu có prompt hay cấu hình nào từng tinh chỉnh trên 5.1 thì nó đang chạy trên model khác.

**Nếu làm được hai việc:** liệt kê mod/plugin đang bật (`claude plugin list`, `/plugin`) và **ghép `permissions.denyInsteadOfPrompting` với một danh sách `deny` tường minh** (mục 3). Đây là đính chính cho khuyến nghị số một của tuần trước: `denyInsteadOfPrompting` quản tầng 1, `deny` là tầng duy nhất với tới mod. Nếu không kể tên được từng mod đang bật, hàng rào chưa đóng.

**Nếu làm được ba việc:** **đừng** bật Code Mode ở bất cứ chỗ nào chạy không người trực — nó đã bị loại kỹ thuật khỏi cloud session, `-p` và Agent SDK, nên câu này chỉ là để không ai thử lách. Thay vào đó: thử nó **một lần, trong một session local dùng được rồi bỏ**, trên đúng một task lặp lại nhiều lần của Project1, và **tự đo** số lượt đi về trước/sau. Vì không ai đo giúp bạn.
